# Audit 017 - Panel CS (admin): desain konsol web & validasi popup

**Tanggal:** 2026-10-11
**Pemicu:** "Admin banyak fitur dan menu di mode mobile tapi tidak ada desain yang detail, padahal Sengketa ada list + action + foto tapi desain tidak mencerminkan aplikasi web. Validasi popup juga tidak ada."
**Skill:** senior-fe (mode After, audit saja, tanpa perubahan kode)
**Dial:** ENERGY 1 / RHYTHM 1 / MOTION 1 (konsol internal, kalem; padat data > hiasan)
**Scope:** seluruh halaman CS (`/admin/*`): Ringkasan, Onboarding, Sengketa, Merchant, Ledger, Inbox.
**Status:** menunggu persetujuan nomor. Belum ada kode yang diubah.

Semua temuan bersumber dari kode (`path:line`), sesuai DNA §8. Yang mustahil dibaca dari sumber (lebar runtime, overflow) tidak diklaim di sini.

---

## Design Read

Konsol CS untuk operator internal, mode **utility**. Satu pohon komponen, dua lebar: web desktop `>=901px` (`_admin-console.scss`) dan PWA 430px di bawahnya (DNA.md, AGENTS §9). Keputusan produk itu tidak dipertanyakan di audit ini, yang dinilai adalah bagaimana isinya memakai kedua lebar itu.

## Temuan

### F-01 (HIGH) - Popup jalur uang memakai pola ponsel di web

- SF: HG-12 (responsif bagian dari desain), PG-14 (template/pola salah konteks).
- Akar: konfirmasi uang (putusan sengketa, batal order, blacklist COD) memakai `ConfirmSheet` (`ConfirmSheet.tsx:29-41`) yang membungkus `BottomSheet` (`BottomSheet.tsx:98-115`). Gaya `.sheet-overlay`/`.sheet-panel` di `_merchant-2.scss:430-464`: `align-items: flex-end`, `max-width: var(--shell-max)` (430px), `margin-inline: auto`, radius hanya atas, animasi `sheet-rise` dari `translateY(100%)`.
- Akibat terukur: di layar 1440px, dialog ini muncul sebagai lembar 430px di dasar jendela (bukan dialog tengah). Tidak ada satu pun `@media` yang mengubah sheet untuk lebar desktop, maksudnya panel CS tidak punya override. Bandingkan: konsol SA memaksa dialog tengah lewat `body:has(.sa-root) .sheet-overlay { align-items: center; justify-content: center }` dan `.sheet-panel { max-width: 520px; border-radius: var(--radius-lg); box-shadow: var(--shadow-md) }` (`_superadmin-2.scss:400-416`). CS tidak.
- Catatan: ini temuan yang paling menjelaskan keluhan "tidak mencerminkan aplikasi web".

### F-02 (HIGH) - Bukti foto hanya angka, tidak bisa dibuka

- SF: HG-06 (kontrol mati), C-5 (bukti bukan klaim).
- Akar: `AdminDisputes.tsx:62-65` merender `<Camera/> {photoCount} foto bukti` (atau "Tanpa foto bukti"); `AdminOnboarding.tsx:79-81` merender `<Image/> {photoCount} foto tempat usaha`. Tidak ada `<img>`, thumbnail, atau viewer di mana pun di role admin (verifikasi: nol `img` di `src/pages/Admin*.tsx` dan `src/components/admin/*`).
- Akibat terukur: CS memutuskan sengketa jalur uang tanpa pernah melihat bukti yang dikirim pengaju. Foto aslinya ada di sisi pengaju (`DisputeSubmit.tsx:238-262`, `.dispute-photos img` 96x96), tetapi tidak pernah menyeberang ke konsol.
- Ini juga bagian dari keluhan "ada foto tapi desain tidak mencerminkan aplikasi web": angka foto berdiri sendiri tanpa cara membukanya.

### F-03 (HIGH) - Popup putusan tanpa validasi

- SF: HG-05 (aksesibilitas termasuk `aria-invalid`/error), HG-07 (state).
- Akar: `AdminDisputes.tsx:88-99` memakai `input[type=range]` mentah untuk refund sebagian, tanpa pesan nilai valid, tanpa cabang error. `ConfirmSheet` (`ConfirmSheet.tsx:3-12`) hanya menerima `title/body/confirmLabel/onConfirm/onClose`, tidak punya field, tidak punya validasi. Tombol "Terapkan putusan"aktif tanpa syarat (`ConfirmSheet.tsx:36-38`).
- Akibat terukur: putusan jalur uang bisa dieksekusi untuk nilai refund berapa pun (10-90), tanpa catatan wajib, tanpa `aria-invalid`. Tidak ada `required`, `setError`, atau teks error di seluruh `Admin*.tsx`.
- Keluhan "validasi popup juga ga ada" cocok persis di sini.

### F-04 (HIGH) - Sengketa desktop tidak punya bentuk web

- SF: C-3 (komposisi mengikuti konten), PG-14.
- Akar: `AdminDisputes.tsx:184-194` menaruh semua kartu di `.admin-section`. Di desktop, `.admin-section` hanya berubah jadi `display: grid; grid-template-columns: repeat(auto-fill, minmax(340px, 1fr))` (`_admin-console.scss:335-340`). Tidak ada master-detail, tidak ada tabel, tidak ada panel detail.
- Akibat terukur: alasan, badge, slider, dan empat tombol resolusi dijejalkan dalam satu `article.admin-card` (agregat ~7 baris teks + kontrol). Operator tidak bisa membandingkan antrean (tidak ada kolom) dan tidak bisa membaca satu sengketa sendirian (detail tidak terpisah).

### F-05 (MEDIUM) - Aksi destruktif tanpa konfirmasi

- SF: HG-06, UX "konfirmasi aksi destruktif".
- Akar: `AdminOnboarding.tsx:100-109` "Tolak onboarding" langsung `dispatch(rejectOnboarding)` + toast, tanpa sheet. `AdminMerchants.tsx:108-117` "Suspend" langsung `dispatch(suspendMerchant)`, tanpa sheet.
- Akibat terukur: tidak konsisten dengan MoneyPath lain di role yang sama: "Blacklist COD" (`AdminMerchants.tsx:118-131` -> `ConfirmSheet` :170-193) dan "Batalkan order" (`AdminDashboard.tsx:287-293` -> sheet :338) justru punya konfirmasi. Dua aksi yang paling merusak (tolak tenant, suspend merchant) tidak.

### F-06 (MEDIUM) - Empty state hilang di tiga daftar

- SF: HG-07.
- Akar: `AdminDashboard.tsx:210-233` "Nominal per jenis entry" dan "Mutasi terbaru" (`.slice(0,5)`) merender kartu tanpa isi saat daftar kosong. `AdminMerchants.tsx:69` memetakan `merchants` tanpa cabang kosong, judul "Daftar merchant (0)" tetap tampil.
- Akibat terukur: kartu berjudul tanpa isi, terlihat seperti gagal render. Halaman lain sudah benar (mis. `AdminDashboard.tsx:262` `admin-empty`, `AdminOnboarding.tsx:56`).

### F-07 (MEDIUM) - Tidak ada loading / error / retry di seluruh role

- SF: HG-07.
- Akar: semua halaman admin membaca Redux mock sinkron (`s.admin.*`). Tidak ada `isLoading`, `error`, atau tombol coba lagi di satu pun `Admin*.tsx`. Satu-satunya state loading di role ini adalah tombol "Periksa sekarang"/"Memeriksa…" (`AdminDashboard.tsx:331-333`, `disabled={checkingUpdate}`).
- Akibat terukur: saat data live (PostgREST/Supabase) belum tiba atau gagal, layar tidak bisa membedakan "kosong" dari "sedang memuat" dari "gagal".

### F-08 (MEDIUM) - Ledger read-only tanpa alat kerja

- SF: C-3, HG-06 (affordance hilang).
- Akar: `AdminLedger.tsx:53` memetakan seluruh `ledger` tanpa batas, tanpa filter/sort/export/pagination; satu-satunya kontrol di halaman adalah lonceng header.
- Akibat terukur: konsol ledger append-only yang seharusnya bisa diaudit, tapi tidak ada cara menyaring, mengurutkan, atau mengekspor. Untuk data nyata (ribuan entry) ini tak terpakai.

### F-09 (MEDIUM) - Mobile: hierarki rata, semua seragam

- SF: PG-10 (kartu seragam), QL-03.
- Akar: di <901px, `.admin-section` hanya `margin-bottom` (`_admin.scss:107-109`), `.admin-card` seragam (`padding var(--space-4)`, `radius var(--radius-lg)`, `margin-bottom var(--space-3)`, `_admin.scss:74-78`). `.admin-kpi` 2 kolom seragam (`_admin-2.scss:120-125`).
- Akibat terukur: setiap layar adalah tumpukan kartu dengan bobot visual sama, jadi tidak ada satu titik fokus. "Banyak fitur dan menu" tapi tidak ada kepadatan khas konsol: tidak ada ringkasan tabel, tidak ada baris informatif, tidak ada detail bertingkat di mobile.

### F-10 (LOW) - Tautan sidebar desktop 32px

- SF: HG-05 (target >=44px).
- Akar: `.admin-side-link { min-height: 32px }` (`_admin-console.scss:162-169`). Ini satu-satunya kontrol interaktif di role admin di bawah 44px (sisanya 44px lewat `--touch-min`).
- Catatan: sidebar hanya tampil di desktop, jadi bukan regresi mobile, tetap menyimpang dari target minimum DNA.

### F-11 (LOW) - Nilai px mentah padahal token ada

- SF: QL-01, DNA §4 ("jangan tulis nilai mentah kalau tokennya ada").
- Akar: `.admin-rank-name { flex: 0 0 104px }` (`_admin.scss:305`), `.admin-rank-bar { height: 8px }` (:312), `.admin-ledger-icon { width/height: 32px }` (:509-510), `.dispute-photo / .dispute-photo-add { width/height: 96px }` (`_admin-2.scss:64-65,103-104`), slider track `6px` (`_admin.scss:460`). Warna semuanya sudah token (nol hex), hanya ukuran yang mentah.
- Akibat terukur: bukan bug tampilan sekarang, tapi menyimpang dari aturan satu sumber nilai.

### F-12 (LOW) - Foto pengaju tanpa lazy/decoding/fallback

- SF: images (skill senior-fe).
- Akar: `DisputeSubmit.tsx:238-262` merender `<img src={url} width={96} height={96}>` tanpa `loading="lazy"`, `decoding="async"`, atau `onError`. Padahal pola rumah ada di `MerchantCard.tsx:32-33` (`loading="lazy"`, `decoding="async"`).
- Catatan: relevan begitu F-02 dikerjakan (foto mulai tampil di konsol, jumlahnya bertambah).

## Yang sudah benar (jangan diutak-atik)

- Satu sumber nav untuk ponsel dan desktop (`adminNav.ts`), badge dari selector yang sama (`pendingTenantCount`, `openDisputeCount`), tidak ada angka berbeda antar bentuk nav.
- Sebagian besar target sentuh sudah 44px (`--touch-min`): tombol, picker, `.admin-link`, `.dispute-photo-remove`, slider, `.inbox-*`.
- Konfirmasi dua langkah sudah ada untuk dua jalur uang (blacklist COD, batal order) dan putusan sengketa.
- Keadaan kosong sudah ada di beberapa tempat (eskalasi, eksposur, antrean onboarding).
- Shell desktop: sidebar sticky, header sticky, bottom nav disembunyikan (`body:has(.admin-console) .bottom-nav { display:none }`), kolom keluar dari kunci 430px. Kerangkanya benar, isinya yang kurang.
- Warna seragam token, nol hex mentah di `system/`.

Aturan validasi (rentang, catatan wajib, siapa berwenang) **UNRESOLVED**, sumber: `docs/product/prd/versions/irbid-mvp-v2-2026-09-21/`. Jangan dikunci sebelum PRD menetapkannya; audit ini hanya mengusulkan bentuk popup, bukan angka aturannya.
- Nama operator di sidebar masih generik ("Admin User", `AdminShell.tsx`); PRD aktif tidak punya requirement auth/operator untuk CS (UNRESOLVED-by-absence), jadi dibiarkan.

## Usul perbaikan (menunggu persetujuan nomor)

1. **Dialog tengah untuk jalur uang (F-01).** Tambah override desktop untuk `.sheet-overlay`/`.sheet-panel` di `_admin-console.scss` (scope `body:has(.admin-console)`), sama pola dengan `body:has(.sa-root)` yang sudah ada. Satu tempat, mobile tidak berubah.
2. **Pindahkan input keputusan ke dalam dialog + validasi (F-03).** Slider refund dan catatan masuk ke sheet; tombol nonaktif sampai valid; `aria-invalid` + teks error. Aturan angkanya ditandai `UNRESOLVED` sampai PRD menetapkannya.
3. **Foto bisa dibuka (F-02).** Thumbnail di kartu sengketa + viewer. Perlu mengalirkan URL foto ke state admin (data sekarang hanya `photoCount`); ini menyentuh `src/types.ts` + `src/data/admin.ts`.
4. **Bentuk web untuk Sengketa (F-04).** Master-detail di desktop: kolom antrean (baris ringkas) + panel detail (bukti, alasan, keputusan). Mobile tetap kartu.
5. **Konfirmasi untuk aksi destruktif (F-05), empty state (F-06), loading/error (F-07), alat ledger (F-08), hierarki mobile (F-09), sisa LOW (F-10..F-12).**

Catatan arah: usul 1-4 mengukuhkan pilihan "satu pohon komponen, cabang di breakpoint 901px", bukan memecah panel CS jadi dua aplikasi. Jangan digabung dengan penyapuan lintas-halaman sebelum nomor 1-4 diputuskan.
